## 使用方式

在 Woodpecker 仓库页面点击 Run pipeline（运行流水线），选择 `openchamber/pindou` 分支，在 Additional pipeline variables（附加流水线变量）中增加名称 `BUILD_TARGET`，填写以下值之一：

- `api`：只执行后端 Ruff 和 pytest，包括隔离的 PostgreSQL 并发测试。
- `web`：只执行前端 ESLint、Vitest、TypeScript 和 Next.js webpack standalone 构建，不创建 PostgreSQL 测试容器。
- `all`：运行两边；未添加变量或值为空时默认两边都运行。

变量值区分大小写。填写错误值时，checkout 在下载源码前退出，避免所有构建步骤被跳过后错误地呈现成功。更换目标应新建流水线，重试旧任务会复用旧变量。

PostgreSQL 直接运行官方 `postgres:17-alpine` 镜像，**不构建数据库镜像**。只在 API 参与时创建任务专用的临时数据库，结束后清理，不使用或更新 NAS 上现有数据库。

## 自动选择规则

- push 修改 `apps/pindou/apps/api/**`、`apps/pindou/deploy/api.Dockerfile`：运行 API 及临时 PostgreSQL。
- push 修改 `apps/pindou/apps/web/**`、`apps/pindou/deploy/web.Dockerfile`：运行 Web。
- `.woodpecker.yaml`、`apps/pindou/.dockerignore`、`apps/pindou/docker-compose.yml`、`apps/pindou/deploy/fnos/**` 变化：两边都运行。
- 同时修改两边则都运行；缺失变更列表时也运行两边。其他仅文档修改会跳过构建步骤。
- API 与 PostgreSQL 复用同一份 YAML 条件锚点，避免 Web 独立构建仍启动测试数据库。
